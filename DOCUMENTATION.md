# Rosetta v3 Documentation

## Обзор

Rosetta v3 - это автоматизированная система перевода научных статей с arXiv с английского на русский язык. Система сохраняет исходную верстку LaTeX, формулы, изображения и библиографию, обеспечивая высокое качество технического перевода с использованием LLM (GPT-4o-mini).

## Архитектура

Система построена по конвейерному (pipeline) принципу. Главный оркестратор (`TranslationOrchestrator`) управляет потоком данных через серию специализированных модулей.

### Схема работы (Pipeline)

1.  **Fetcher (Загрузка):** Скачивание исходного кода статьи с arXiv.
2.  **Flattening (Сплющивание):** Рекурсивное объединение всех `\input` и `\include` файлов в один большой LaTeX-файл для целостной обработки.
3.  **Masking (Маскирование):** Агрессивное скрытие непереводимых элементов (формулы, код, таблицы, сложные команды) специальными токенами.
4.  **Splitting (Разбиение):** Умное разбиение текста на чанки (chunks), которые помещаются в контекстное окно LLM, с сохранением границ параграфов и секций.
5.  **Translation (Перевод):** Параллельный или последовательный перевод чанков через OpenAI API.
6.  **Assembly & Restoration (Сборка):** Сборка переведенных чанков и восстановление скрытых элементов по токенам.
7.  **Cyrillization (Кириллизация):** Инъекция пакетов поддержки русского языка (`babel`, `fontenc` T2A) и исправление шрифтов.
8.  **Post-processing (Постобработка):** Исправление типовых ошибок генерации и форматирования.
9.  **Compilation (Компиляция):** Сборка итогового PDF с помощью `pdflatex`.

## Ключевые компоненты

### 1. TranslationOrchestrator (`pipeline/translator.py`)
Центральный компонент, связывающий все этапы. Управляет состоянием перевода, обрабатывает ошибки на каждом этапе и обеспечивает передачу данных между модулями.

### 2. ArxivFetcher (`pipeline/arxiv_fetcher.py`)
Отвечает за взаимодействие с arXiv API и скачивание исходников (source tarball). Распаковывает архив и находит главный `.tex` файл.

### 3. ContentMasker (`pipeline/masker.py`)
**Критически важный модуль.** Использует набор регулярных выражений для защиты контента, который **не должен** быть переведен:
- Математические формулы (inline `$`, display `$$`, `equation`, `align` и т.д.).
- Окружения кода (`verbatim`, `lstlisting`, `minted`).
- Специализированные графические пакеты (`tikz`, `xy-pic`).
- Команды вставки изображений (`\includegraphics`).
- Сложные LaTeX команды (`\cite`, `\ref`, `\label`).

Элементы заменяются на токены вида `<<MATH_DISP_0>>`, `<<CODE_1>>`, что предотвращает их искажение языковой моделью.

### 4. ContentSplitter (`pipeline/splitter.py`)
Разбивает маскированный текст на части.
*   **Стратегия:** Пытается разбить по границам секций (`\section`). Если секция слишком большая — по подсекциям или параграфам.
*   **Особенности:**
    *   Выделяет преамбулу (Preamble) в отдельный чанк (часто не требует перевода или требует особого подхода).
    *   Выделяет библиографию (`thebibliography`) и исключает её из перевода, чтобы не испортить ссылки.

### 5. OpenAIClient (`integrations/openai_client.py`)
Обертка над API OpenAI.
*   **Модель:** GPT-4o-mini (оптимальна по цене/качеству для этой задачи).
*   **Кэширование:** Кэширует системные промпты для экономии токенов.
*   **Устойчивость:** Реализует экспоненциальную задержку (backoff) при ошибках API (Rate Limits, Timeouts).
*   **Промпт:** Использует оптимизированный, компактный системный промпт с инструкциями "не ломать LaTeX".

### 6. LaTeXRestorer (`pipeline/assembler.py`)
Заменяет токены перевода (`<<MATH_DISP_0>>`) обратно на оригинальный исходный код. Проверяет целостность (чтобы все токены вернулись на место) и сообщает о "галлюцинированных" токенах.

### 7. PDFCompiler (`pipeline/pdf_compiler.py`)
Запускает `pdflatex` в изолированной среде. Предпринимает несколько попыток компиляции (так как LaTeX часто требует 2-3 прогона для корректных ссылок).

### 8. NotionClient (`integrations/notion_client.py`)
Интеграция с Notion API для автоматического сохранения результатов переводов.
*   **Функции:** Создание страниц в базе данных Notion с метаданными статей, ссылками на PDF файлы и информацией о переводе.
*   **Метаданные:** Сохраняет название статьи, arXiv ID, авторов, категории, дату перевода, ссылку на оригинал.
*   **Устойчивость:** Ошибки отправки в Notion не прерывают работу Discord бота.

## Тонкие моменты и "Gotchas"

### Рекурсивный Input
Многие статьи разбиты на десятки файлов (`chapter1.tex`, `fig1.tex`). Система **рекурсивно** вставляет содержимое этих файлов в главный файл перед обработкой. Это упрощает контекст для LLM, но делает файл огромным.

### Агрессивное маскирование
LLM часто пытаются "исправить" или "перевести" формулы, что недопустимо. Поэтому мы полностью скрываем их.
*   *Нюанс:* Вложенные конструкции (например, `\text{...}` внутри формулы) могут быть скрыты и не переведены. Текущая реализация не парсит глубокую вложенность идеально, полагаясь на регулярные выражения.

### Кириллизация и шрифты
Просто добавить русский текст в LaTeX недостаточно.
*   Система автоматически добавляет `\usepackage[T2A]{fontenc}` и `\usepackage[russian]{babel}`.
*   **Важно:** Многие стилевые файлы конференций (например, `nips_2017.sty`, `cvpr.sty`) жестко задают шрифты (Times, Helvetica), которые не имеют кириллицы.
*   **Решение:** Оркестратор патчит `.sty` файлы, закомментируя строки типа `\renewcommand{\rmdefault}{ptm}`, позволяя работать стандартным шрифтам Computer Modern (которые поддерживают кириллицу через `cmap`/`fontenc`).

### Библиография
Библиография (`.bbl` или environment `thebibliography`) содержит много технических данных. Перевод названий статей обычно не требуется и вреден (сложнее найти оригинал). Система детектирует блок библиографии и исключает его из процесса перевода, восстанавливая в оригинальном виде.

### Arxiv Stamp
Чтобы сохранить вид оригинального PDF, система генерирует и вставляет вертикальный штамп с номером arXiv на полях документа (аналог того, что делает сам arXiv), но добавляет туда дату и категорию.

## Конфигурация

Настройки находятся в `config.py`. Основные параметры:
*   `OPENAI_API_KEY`: Ключ API (через env var или файл `api_key.txt`).
*   `OPENAI_MODEL`: По умолчанию `gpt-4o-mini`.
*   `MAX_CHUNK_TOKENS`: Размер чанка для перевода (по умолчанию ~1500 токенов).
*   `NOTION_TOKEN`: Токен интеграции Notion (опционально, для сохранения переводов в Notion).
*   `NOTION_DATABASE_ID`: ID базы данных Notion (опционально).

### Настройка Notion интеграции

1. **Создание интеграции:**
   * Перейдите на https://www.notion.so/my-integrations
   * Создайте новую интеграцию (Internal Integration)
   * Скопируйте Integration Token

2. **Структура базы данных:**
   Система поддерживает настраиваемые названия свойств. По умолчанию используются следующие свойства:
   * `Title` (Title) - название статьи (первое свойство базы данных)
   * `Авторы` (Text/Rich Text) - авторы статьи
   * `Дата добавления` (Date) - дата добавления перевода
   * `Резюме` (Text/Rich Text) - краткое описание (abstract) статьи
   * `Ссылка` (URL) - ссылка на оригинал статьи на arXiv
   * `Статус чтения` (Select) - статус чтения статьи
   * `Вид` (Select) - тип публикации (статья/книга и пр.)
   * `Тема` (Text/Rich Text) - тема/категория статьи

3. **Настройка названий свойств (опционально):**
   Если ваши свойства называются по-другому, добавьте в `.env`:
   ```
   NOTION_PROP_TITLE=Название
   NOTION_PROP_AUTHORS=Авторы
   NOTION_PROP_DATE=Дата добавления
   NOTION_PROP_SUMMARY=Резюме
   NOTION_PROP_LINK=Ссылка
   NOTION_PROP_STATUS=Статус чтения
   NOTION_PROP_TYPE=Вид
   NOTION_PROP_TOPIC=Тема
   NOTION_DEFAULT_TYPE=Статья
   NOTION_DEFAULT_STATUS=Не прочитано
   ```

4. **Подключение интеграции к базе:**
   * Откройте базу данных в Notion
   * Нажмите "..." → "Connections" → выберите вашу интеграцию

5. **Добавление в .env:**
   ```
   NOTION_TOKEN=secret_...
   NOTION_DATABASE_ID=...
   ```

**Важно:** 
- Названия свойств должны совпадать **точно** с названиями в вашей базе данных Notion
- Типы свойств должны соответствовать (Title, Text/Rich Text, Date, URL, Select)
- Значения для Select полей (`Статус чтения`, `Вид`) должны существовать в вашей базе данных

## Использование

Через CLI:
```bash
python3 cli.py 1706.03762
```
Или:
```bash
python3 cli.py https://arxiv.org/abs/1706.03762
```

Результаты сохраняются в папке `temp/<arxiv_id>/source/`, итоговый файл — `translated.pdf`.

## Discord Bot

Система включает Discord бота для удобного запуска переводов через команду `/rosetta`.

### Настройка Discord бота

1. Создайте бота в Discord Developer Portal (https://discord.com/developers/applications)
2. Скопируйте Bot Token
3. Добавьте в `.env`:
   ```
   DISCORD_BOT_TOKEN=ваш_токен
   ```
4. Пригласите бота на сервер с правами на отправку сообщений и файлов

### Использование

В Discord используйте команду:
```
/rosetta arxiv_link:1706.03762
```

Бот автоматически:
1. Загрузит статью с arXiv
2. Выполнит перевод
3. Отправит PDF файлы в Discord
4. Сохранит результат в Notion (если настроено)
