# План разработки Rosetta_v3

## Обзор проекта

**Rosetta_v3** — система автоматизированного перевода научных статей с arXiv с английского на русский с полным сохранением форматирования LaTeX.

**Версия 3** представляет собой переработанную архитектуру с фундаментальными принципами:
- **Агрессивное маскирование** — формулы и графика заменяются на токены перед переводом
- **Хирургическое исправление** — итеративное исправление ошибок компиляции
- **Кириллизация** — автоматическое внедрение поддержки русского языка
- **Разделяй и властвуй** — разбиение на логические чанки для сохранения контекста

**Цель:** Реализовать надёжную систему перевода, которая работает с любыми шаблонами LaTeX, обеспечивает максимально точный и подробный перевод без потери сегментов, абзацев и глав, с полным сохранением форматирования, **при минимизации затрат на OpenAI API**.

## Фундаментальные принципы v3

Новая версия системы построена на следующих ключевых принципах:

### 1. Разделяй и Властвуй (Chunking)
Статья разбивается на логические части (секции), чтобы не терять контекст при переводе больших документов.

### 2. Агрессивное Маскирование (No-Code Translation)
Формулы, TikZ-графика и сложные команды заменяются на токены (`<<MATH_01>>`, `<<TIKZ_02>>`) перед переводом. GPT не видит кода, поэтому не может его сломать. Это критически важно для сохранения целостности математических формул и специализированной графики.

### 3. Хирургическое исправление (Surgical Repair)
Ошибки компиляции исправляются итеративно, анализируя лог и меняя только сломанную строку, а не весь файл. Это позволяет точно локализовать и исправить проблемы без пересоздания всего документа.

### 4. Кириллизация
Автоматическое внедрение поддержки русского языка (babel, T2A, utf8) перед компиляцией, гарантируя корректное отображение кириллицы в итоговом PDF.

### 5. Специализированная валидация (Разделение ошибок)
Валидация разделена на два типа для эффективности и надежности:

**Ошибки кода (LaTeX не компилируется):**
- **Проблема старого подхода:** GPT плохо видит свои ошибки, говорит "Код верный", а pdflatex выдаёт ошибку
- **Решение v3:** 
  - **Маскирование** — GPT вообще не видит кода, ошибок не возникает
  - **Surgical Fixer** — если ошибка всё же просочилась, LLM исправляет только конкретную ошибку из лога компиляции, а не весь текст

**Ошибки смысла (Пропущенные абзацы, галлюцинации):**
- **Проблема старого подхода:** GPT перечитывает свой перевод — дорого и ненадежно (модель подтверждает свою галлюцинацию)
- **Решение v3:** 
  - **Программная валидация** (Validator на Python) — подсчёт абзацев, токенов, секций
  - Логика: "В оригинале было 5 разрывов строк. В переводе — 4. Тревога!"
  - Бесплатно, мгновенно и надёжнее чем GPT-валидация

**Итог:** Убрана дорогая GPT-валидация "проверь сама себя". Вместо неё — быстрая программная проверка и LLM-исправление только по факту ошибки компиляции.

## Архитектура системы

Система состоит из следующих основных компонентов:

1. **CLI Interface** — точка входа для пользователей
2. **Translation Pipeline Orchestrator** — координация всех этапов
3. **ArxivFetcher** — загрузка и организация папок
4. **LaTeX Tokenizer & Masker (CORE)** — маскирование кода и формул (новый критический компонент)
5. **Content Splitter** — разбиение текста на семантические чанки (новый компонент)
6. **OpenAI Client** — перевод маскированного текста
7. **LaTeX Restorer & Assembler** — сборка и восстановление кода (новый компонент)
8. **Deterministic Post-processor** — Regex-исправления типичных ошибок
9. **Iterative PDF Compiler (Surgical Fixer)** — компиляция с исправлением ошибок
10. **Validator** — проверка структуры перед сборкой
11. **Glossary Manager** — управление терминологическим словарём

### Структура директорий v3

Система работает в директории `downloads/`:

```
Rosetta_v2/
├── downloads/
│   └── {arxiv_id}/           # Создается Fetcher'ом
│       ├── source/           # Распакованный исходный код (.tex, .bib, images)
│       ├── original.pdf      # Скачанный оригинал
│       ├── translated.pdf    # Итоговый результат
│       ├── translated.tex    # Переведенный LaTeX
│       ├── translation_report.json
│       └── debug/            # Промежуточные файлы
│           ├── 01_masked_content.json
│           ├── 02_chunks_translated.json
│           └── compiler_logs/
├── ... (остальная структура)
```

## Принципы оптимизации стоимости OpenAI API

**Критически важно:** Система должна минимизировать затраты на OpenAI API, сохраняя при этом высочайшее качество перевода.

**Ключевое изменение v3:** Убрана дорогая GPT-валидация "проверь сама себя". Вместо неё используется быстрая программная проверка (подсчёт абзацев, токенов, секций), что экономит значительные средства и делает валидацию более надёжной.

### 1. Оптимизация промптов

**Стратегии:**
- [ ] **Минимизация системного промпта:**

  - Оптимизировать форматирование промпта
  - Избегать повторений одинаковых правил
  
- [ ] **Компактный глоссарий:**
  - Формат "ключ: значение" вместо длинных описаний
  - Только релевантные термины для статьи (не весь глоссарий)
  - Группировка похожих терминов
  - Использование компактного JSON формата
  
- [ ] **Оптимизация структуры промпта:**
  - Примеры только при необходимости

  - Оставить только переводимый текст + контекст структуры
  - **Экономия токенов:** tikz код может быть очень большим, удаление его из промпта экономит много токенов

## Риски и митигация

### Риск 1: Сложность парсинга LaTeX и поддержка любых шаблонов
**Митигация:** 
- Использовать существующие библиотеки (например, pylatexenc) если нужно
- Начать с простых случаев, постепенно усложнять
- Тщательное тестирование на реальных документах с различными шаблонами
- **Расширенное тестирование граничных условий** для каждого типа элементов
- Поддержка fallback стратегий для нестандартных конструкций

### Риск 2: Ошибки компиляции PDF
**Митигация:**
- Подробное логирование вывода pdflatex
- Автоматическое исправление типичных проблем
- Fallback стратегии для проблемных документов

### Риск 3: Rate limits API
**Митигация:**
- Реализовать retry с exponential backoff
- Кэширование результатов где возможно
- Обработка rate limit errors с понятными сообщениями

### Риск 4: Большие документы (>128K токенов)
**Митигация:**
- Проверка размера перед переводом
- Показ предупреждения пользователю
- Возможность разбиения на сегменты (будущая функция)

### Риск 5: Потеря сегментов, абзацев или глав при переводе
**Митигация:**
- **Тщательная валидация полноты** структуры документа
- **Детальное тестирование** всех граничных условий в Validator
- **Проверка счётчиков** элементов (секций, абзацев, глав)
- **Анализ .log файла** на наличие предупреждений о пропущенных элементах
- Усиленные инструкции в промпте GPT о сохранении структуры

### Риск 6: Снижение качества при оптимизации стоимости
**Митигация:**
- **Обязательная проверка качества** после каждой оптимизации промпта
- Сравнение переводов до и после оптимизации
- Тестирование на реальных статьях после оптимизации
- **Итеративная оптимизация** с проверкой качества на каждом шаге
- Откат оптимизаций, если качество снижается
- Метрики качества: валидация должна показывать высокие результаты после оптимизации

### Риск 7: Переоптимизация промпта (потеря критичных инструкций)
**Митигация:**
- Сохранение всех критичных инструкций в оптимизированном промпте
- Проверка наличия всех необходимых правил после оптимизации
- Тестирование на граничных случаях после каждой оптимизации
- Документирование всех изменений в промпте
- Версионирование промптов для возможности отката

### Риск 8: Сложная вложенность LaTeX (v3: маскирование)
**Митигация:**
- Использовать `pylatexenc.latexwalker` для настоящего парсинга дерева, а не просто Regex
- Тестирование на сложных вложенных структурах (tikz внутри figure, формулы внутри tikz)
- Детальное логирование случаев некорректного маскирования
- Fallback стратегии для неподдерживаемых конструкций

### Риск 9: Surgical Fixer зацикливается (v3: хирургическое исправление)
**Митигация:**
- Лимит итераций (10). Если не помогло — откат к предыдущей версии или пропуск проблемного блока (закомментировать)
- Проверка что исправление не создает новые ошибки
- Логирование всех попыток исправления
- Анализ паттернов ошибок для предотвращения зацикливания

### Риск 10: Проблемы с кодировками (v3: кириллизация)
**Митигация:**
- Жесткое принуждение к UTF-8 везде для .tex файлов
- Fallback на latin-1 для .log файлов (LaTeX выводит в latin-1)
- Тестирование на различных системах (Windows/Linux/Mac)
- Валидация корректности отображения кириллицы в итоговом PDF
