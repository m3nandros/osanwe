# Техническое задание: Модуль General PDF для Rosetta v3

## 1. Цель проекта
Расширить возможности системы Rosetta, добавив поддержку перевода произвольных PDF-документов (научные статьи, техническая документация, книги) с сохранением верстки, формул и иллюстраций, используя метод реконструкции (Reverse Engineering).

## 2. Архитектура и Структура
Новый функционал реализуется как отдельный подмодуль в директории `pipeline/`, независимый от текущего пайплайна arXiv, но использующий общие утилиты (OpenAI Client, Logger, Config).

### 2.1. Новые компоненты
*   **`pipeline/pdf_pipeline/`** — корневая папка нового модуля.
    *   **`extractor.py`**: Отвечает за конвертацию PDF -> Markdown. Извлекает текст, формулы (в формате LaTeX), таблицы и сохраняет изображения.
    *   **`translator.py`**: Адаптированная логика перевода. Принимает Markdown, разбивает его на смысловые блоки, переводит через LLM, сохраняя Markdown-разметку.
    *   **`generator.py`**: Отвечает за сборку финального PDF. Конвертирует переведенный Markdown -> LaTeX (через Pandoc) -> PDF.
    *   **`layout_detector.py`**: Анализирует исходный PDF, чтобы определить тип верстки (одна колонка vs две колонки) для выбора правильного шаблона.
    *   **`templates/`**: Папка с универсальными LaTeX-шаблонами (`article_template.tex`, `book_template.tex`).

## 3. Логика работы (Data Flow)

### Этап 1: Прием и Анализ
1.  Система получает PDF файл.
2.  `LayoutDetector` определяет тип документа:
    *   **Тип:** Статья (Article) или Книга (Book).
    *   **Верстка:** 1 колонка или 2 колонки.
3.  Создается рабочая директория `temp/<pdf_name>/`.

### Этап 2: Экстракция (Extraction)
1.  Используется библиотека **`marker-pdf`** (или аналог `surya`/`nougat`).
2.  PDF преобразуется в структурированный **Markdown**.
3.  Формулы распознаются и конвертируются в LaTeX-блоки (`$$...$$`).
4.  Картинки извлекаются в папку `temp/<pdf_name>/images/`.
5.  Ссылки на картинки в Markdown прописываются относительно рабочей папки.

### Этап 3: Перевод (Translation)
1.  Markdown разбивается на чанки (Chunks). В отличие от arXiv (где разбивка идет по строкам LaTeX), здесь разбивка идет по **параграфам** и **заголовкам** Markdown.
2.  LLM получает инструкцию переводить текст, но не трогать синтаксис Markdown (жирный шрифт, ссылки на картинки, LaTeX-формулы).
3.  Специальная обработка для больших книг: последовательный перевод с сохранением контекста (глоссария) между главами.

### Этап 4: Генерация (Generation)
1.  Переведенный Markdown собирается в один файл.
2.  Утилита **Pandoc** конвертирует Markdown в LaTeX, используя подготовленный шаблон (выбранный на Этапе 1).
    *   *Шаблон включает:* поддержку кириллицы (babel, fontenc), настройки шрифтов, настройки полей.
3.  Вставка картинок: Pandoc автоматически генерирует код `\includegraphics` для картинок.
4.  Финальная компиляция LaTeX -> PDF (используя `pdflatex` или `xelatex`).

## 4. Пользовательский интерфейс (UX)
Интеграция в существующий Discord-бот.

*   **Единая точка входа:** Команда `/rosetta`.
*   **Автоматическая маршрутизация:**
    *   Если аргумент — **arXiv ID** (напр. `1706.03762`) -> Запуск существующего arXiv Pipeline (Приоритет 1, так как дает лучшее качество).
    *   Если прикреплен **файл .pdf** -> Запуск нового PDF Pipeline.
    *   Если аргумент — **URL на .pdf** -> Скачивание файла -> Запуск нового PDF Pipeline.

## 5. Технический стек и зависимости
Для реализации потребуются новые системные и Python зависимости:

1.  **System Dependencies (На сервере):**
    *   `pandoc`: Для конвертации Markdown -> LaTeX.
    *   `poppler-utils`: Для работы с PDF (рендеринг страниц).
2.  **Python Libraries:**
    *   `marker-pdf`: Основной движок OCR и экстракции (требует PyTorch).
    *   `pymupdf` (fitz): Вспомогательные операции с PDF.
    *   `pypandoc`: Python-обертка для Pandoc.

## 6. Ограничения и Риски
1.  **Ресурсоемкость:** Библиотека `marker` использует нейросети. Для быстрой работы желателен GPU, но на CPU работать будет (медленнее).
2.  **Точность верстки:** При сложной верстке (плавающие врезки, сложный обтекаймый текст) порядок блоков в Markdown может нарушиться.
3.  **Книги:** Перевод книги в 300 страниц может занять длительное время и потребовать значительных затрат токенов API. Требуется механизм "Resume" (продолжить перевод, если упало).
