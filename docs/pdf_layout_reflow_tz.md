# Техническое задание (ТЗ): PDF Translation Layout Reflow (Variant B)

## 0. Статус и область действия документа

- Этот документ описывает **новый модуль** перевода PDF-научных статей с **сохранением исходной визуальной структуры** (layout fidelity) и **рефлоу** текста при увеличении длины перевода.
- Документ является **ТЗ/спецификацией**. Реализация модулей, выбор библиотек и интеграция в пайплайн выполняются отдельными задачами.
- В репозитории уже существует пайплайн `pipeline/pdf_reconstruct` (Variant A) с реконструкцией через Markdown→LaTeX/Typst с универсальными шаблонами. **Variant B (этот документ) дополняет Variant A** и нацелен на гораздо более точное воспроизведение геометрии/стилей оригинального PDF.

## 1. Цель

Сделать перевод PDF-статей (когда исходники LaTeX отсутствуют) так, чтобы:

- **Визуальная структура и оформление сохранялись максимально идентично оригиналу**.
- **Размеры шрифтов не менялись** (никакого auto-fit, уменьшения кегля или масштаба текста ради «влезания»).
- При увеличении длины текста после перевода происходил **рефлоу**:
  - перенос строк внутри исходных контейнеров/колонок;
  - перенос переполнения на последующие страницы;
  - при необходимости вставка новых страниц.
- **Фиксированные элементы** (логотипы, служебные надписи, элементы оформления, коды/штампы и т.п.) сохраняли **точные координаты и размер**.
- **Плавающие элементы** (рисунки, таблицы, диаграммы, их подписи) могли **перемещаться** по потоку/между страницами, чтобы освободить место под расширившийся текст, но без потери семантики и читаемости.

## 2. Термины и определения

- **Layout Reflow**: переразмещение текстового потока при неизменном кегле/стилях, с добавлением/переразметкой страниц, чтобы избежать наложений/обрезки.
- **Fixed element (фиксированный элемент)**: объект, который должен остаться на **тех же координатах** исходного листа (в рамках системы координат страницы) и с тем же размером.
  - Примеры: логотип издателя, watermark, шапка/подвал (если это бренд/служебная строка), боковые штампы, декоративные рамки.
- **Floating element (плавающий элемент)**: объект, разрешённый к **перемещению** по потоку контента (в пределах страницы/между страницами), чтобы оптимально разместить текст.
  - Примеры: рисунки, таблицы, диаграммы, блоки «Figure/Table caption», элементы, на которые есть ссылки в тексте.
- **Flow text (потоковый текст)**: основной переводимый текст (абзацы, списки, заголовки, подписи к рисункам/таблицам).
- **DocumentDOM**: внутренний «договор данных» (data contract) для представления документа как структуры страниц, блоков, стилей, связей и якорей.

## 3. Вход / выход

### 3.1. Вход

- PDF файл локально или URL (включая «страница статьи», требующая резолвинга до PDF).
- `target_lang` (строка, по умолчанию `ru`).

### 3.2. Выход

- Переведённый PDF.
- Имя выходного файла: **`original_article_title_{target_language_name}.pdf`**.
  - `original_article_title` берётся из исходного документа (метаданные PDF или распознанный заголовок на первой странице) **до перевода**.
  - `{target_language_name}` — нормализованное значение `target_lang` (например, `ru`).
  - Требования к нормализации имени:
    - заменить пробелы на `_`;
    - удалить/заменить на `_` символы кроме `A-Za-zА-Яа-я0-9._-`;
    - обрезать до разумной длины (например, 120 символов), чтобы избежать проблем файловой системы;
    - гарантировать ненулевое имя (fallback: `paper_ru.pdf`).

## 4. Нефункциональные требования

- **Качество перевода**: академический стиль, терминологическая точность, отсутствие деградации качества ради скорости.
- **Повторяемость**: при включённом кэше повторный прогон даёт детерминированные результаты (в пределах влияния LLM).
- **Надёжность**:
  - resumable pipeline (возобновление после падений);
  - устойчивость к частичным ошибкам экстракции.
- **Безопасность**: не утекать PDF/контент в логи; хранить артефакты в явной рабочей папке.

## 5. Используемая модель перевода

- Требуемая модель перевода: **GPT-5-mini**.
- Техническое соответствие в коде/конфиге: **`OPENAI_MODEL=gpt-4o-mini`**.
- Любые оптимизации (параллелизм, чанкинг, кэш, ретраи) должны быть **output-preserving** и не ухудшать качество.

## 6. Общая архитектура (multi-agent)

Variant B рекомендуется реализовать как **оркестрацию нескольких специализированных агентов/подсистем**, каждая с чётким контрактом.

### 6.1. Роли агентов (логические)

- **Layout Analysis Agent (CV/структурный)**
  - строит DocumentDOM: страницы, колонки, контейнеры, bbox, стили, порядок чтения.
- **Content Classification Agent**
  - помечает элементы как fixed/floating/flow/untranslatable.
- **Translation Agent**
  - переводит только `flow` сегменты согласно правилам сохранения структуры.
- **Reflow Engine**
  - выполняет раскладку переведённого текста с сохранением кегля, создаёт новые страницы при переполнении.
- **Verification Agent**
  - проверяет:
    - геометрию (нет наложений/обрезки, фиксированные элементы на месте);
    - качество языка (стиль/термины);
    - корректность ссылок/нумерации.

### 6.2. Границы ответственности

- Переводчик не принимает решений о геометрии.
- Reflow Engine не меняет содержимое текста (кроме типографики: переносы/разрывы строк).
- Классификатор фиксирует политику переводимости и закрепления.

## 7. Data contract: DocumentDOM

### 7.1. Версионирование

- `document_dom_version`: integer (начать с `1`).
- Любые изменения схемы должны быть backward-compatible либо сопровождаться миграторами.

### 7.2. Корневой объект

Минимально необходимый контракт (JSON-представление):

- `document`:
  - `document_dom_version`: 1
  - `source`:
    - `input`: исходный ввод (url/path)
    - `resolved_pdf_path`: путь к staged PDF
    - `sha256`: хэш исходного PDF
  - `metadata`:
    - `title`: строка | null
    - `authors`: массив строк | пусто
    - `doi`: строка | null
    - `lang_detected`: строка | null
  - `page_size`:
    - `unit`: `pt`
  - `pages`: массив `Page`
  - `assets`: словарь `{asset_id: Asset}`

### 7.3. Page

- `page_index`: 0-based
- `width_pt`, `height_pt`
- `rotation_deg`
- `elements`: массив `Element`
- `reading_order`: массив `element_id` (опционально)
- `regions` (опционально): колонки/контентные области

### 7.4. Element (унифицированная модель)

Каждый элемент обязан иметь:

- `id`: строка (уникально в документе)
- `type`: enum
  - `text_span`, `text_block`, `image`, `vector`, `table`, `figure`, `caption`, `equation`, `header`, `footer`, `watermark`, `annotation`
- `page_index`
- `bbox`: `{x0, y0, x1, y1}` в `pt` (origin: левый верх или левый нижний — выбрать и зафиксировать в контракте; рекомендовано: левый верх).
- `z_index`: number (для слоёв)
- `style` (для текстовых):
  - `font_family`
  - `font_size_pt`
  - `font_weight` (optional)
  - `italic` (optional)
  - `color_rgba` (optional)
  - `line_height_pt` (optional)
  - `letter_spacing_pt` (optional)
  - `alignment` (left/center/right/justify)
- `content`:
  - для текста: `text`
  - для изображений/векторов: `asset_ref`
- `policy`:
  - `translate`: bool
  - `fixed`: bool
  - `float`: bool
  - `anchor` (optional): связи с другими элементами
    - `anchor_to`: `element_id` (например, figure к абзацу, caption к figure)
    - `anchor_kind`: enum (`callout_near`, `caption_of`, `footnote_of`, ...)

### 7.5. Дополнительные производные представления

- `FlowGraph` (внутренний): список потоков (`flow_id`) с элементами в порядке чтения.
- `LayoutConstraints` (внутренний): ограничения для reflow (колонки, доступные области, запреты пересечений с fixed).

## 8. Правила переводимости и сохранения

### 8.1. Что переводить

Переводить (по умолчанию):

- заголовки, подзаголовки;
- основной текст (абзацы);
- списки;
- подписи к рисункам/таблицам;
- элементы в таблицах (если это текст, а не числовые коды).

Не переводить (по умолчанию):

- математические формулы (LaTeX/Math);
- идентификаторы, коды, номера грантов (по эвристике);
- имена авторов (как сущности), ORCID;
- DOI/URL;
- служебные строки издателя/копирайт;
- (опционально) раздел `References`/`Bibliography`.

### 8.2. Политика для fixed элементов

- `policy.fixed=true` означает:
  - bbox на странице **не меняется**;
  - размер/масштаб визуального контента **не меняется**;
  - содержимое текста по умолчанию **не переводится**.

Допускается исключение (явная настройка):

- page numbers (если требуется пересчитать номера страниц):
  - позиция/стиль фиксированы;
  - контент может измениться.

### 8.3. Политика для floating элементов

- `policy.float=true` означает:
  - элемент может перемещаться по потоку и между страницами;
  - элемент должен сохранять связность с caption (если есть);
  - элемент не должен перекрывать fixed-области;
  - размер сохраняется, если объект помещается в доступной области.

Fallback (строго по приоритету, если объект не помещается):

- перенос на следующую страницу;
- перенос в отдельную страницу «float-only»;
- только если иначе невозможно: масштабирование вниз в пределах заданного лимита (например, не более 5–10%) или разбиение таблицы.

### 8.4. Жёсткое требование: кегль неизменен

- Для всех переводимых текстовых стилей `font_size_pt` должен быть **идентичен** исходному.
- Запрещены стратегии:
  - уменьшение шрифта «чтобы влезло»;
  - уменьшение межбуквенных интервалов как компенсация;
  - глобальный масштаб страницы.
- Разрешены стратегии:
  - переносы строк/слов;
  - увеличение количества страниц;
  - перемещение floating элементов.

## 9. Reflow Engine: алгоритм раскладки (концептуально)

### 9.1. Вход

- `DocumentDOM` + `FlowGraph`
- переведённые сегменты текста (с привязкой к элементам/параграфам)
- `LayoutConstraints`

### 9.2. Выход

- `ReflowedDocument`:
  - новая последовательность страниц (исходные + добавленные)
  - позиционирование flow и float элементов
  - слой fixed элементов (overlay)

### 9.3. Основной принцип

- Сохраняем исходные **колонки, ширины, поля**.
- Внутри колонок выполняем композицию текста с теми же стилями.
- При переполнении:
  - продолжаем в следующей колонке/следующей странице;
  - при необходимости создаём новые страницы.

### 9.4. Запреты

- Никаких пересечений:
  - flow текст не должен перекрывать fixed элементы;
  - flow текст не должен перекрывать float элементы;
  - float элементы не перекрывают fixed.
- Никакой обрезки текста за границы доступной области.

### 9.5. Якорение float элементов

- У каждого float должен быть `anchor_to` (абзац/раздел/callout), если его можно восстановить.
- Правило: float должен быть размещён как можно ближе к anchor, но допускается перенос на следующую страницу.

## 10. Renderer: варианты реализации

### 10.1. Требования к renderer

- Уметь:
  - рисовать fixed элементы точно по координатам;
  - размещать потоковый текст в колонках с переносом страниц;
  - учитывать изображения/таблицы как float.

### 10.2. Рекомендуемые подходы (на уровне ТЗ)

- **Подход A: Typst как движок верстки + слой fixed overlay**
  - fixed элементы размещаются через `place(...)` в абсолютных координатах;
  - flow/floats через потоки и колонки;
  - компиляция в PDF.
- **Подход B: прямое редактирование PDF**
  - извлечение объектов, перегенерация текстовых потоков, добавление страниц.

Выбор подхода должен обеспечивать выполнение требований разделов 8–9.

## 11. Логи, артефакты и структура output

Рекомендуемая структура (совместима по духу с текущим `pdf_reconstruct`):

- `<out>/<paper_id>/original.pdf`
- `<out>/<paper_id>/bundle/manifest.json`
- `<out>/<paper_id>/bundle/document.dom.json` (DocumentDOM)
- `<out>/<paper_id>/bundle/paper.flow.json` (FlowGraph)
- `<out>/<paper_id>/bundle/paper.<lang>.translated.json` (переведённые сегменты)
- `<out>/<paper_id>/bundle/logs/*`
- `<out>/<paper_id>/<original_article_title>_<lang>.pdf`

## 12. Edge cases (минимальный перечень)

- **2 колонки + float на всю ширину** (рисунок/таблица spanning columns).
- **Сложные таблицы**:
  - широкие; многострочные; многостраничные; с объединёнными ячейками.
- **Подписи, вынесенные в отдельные блоки** (caption далеко от figure).
- **Сноски**:
  - footnotes привязаны к месту; при рефлоу должны оставаться на странице с маркером.
- **Сканированные PDF**:
  - нет текстового слоя; нужен OCR; стиль/шрифты восстанавливаются приближённо.
- **Смешанные языки** (английский + латинские термины + формулы).
- **Hyphenation и переносы**:
  - запрет ломать формулы/DOI/URL;
  - допустимо включать словарные переносы для русского.
- **Rotated pages / landscape**.
- **Фоновые водяные знаки**.
- **Нумерация рисунков/таблиц**:
  - сохранять номера;
  - следить за корректной локализацией «Figure/Fig./Table».

## 13. Критерии приёмки (acceptance)

### 13.1. Геометрия и верстка

- **Font-size invariance**:
  - для всех текстовых стилей, соответствующих исходным, кегль совпадает.
- **Fixed элементы**:
  - координаты bbox совпадают с оригиналом в пределах допуска (например, ≤ 0.5 pt);
  - визуальный контент не деградирует (pixel diff / SSIM для фиксированных областей).
- **Отсутствие артефактов**:
  - нет наложений текста/картинок;
  - нет обрезанных строк;
  - нет выхода за поля.
- **Reflow поведение**:
  - при увеличении текста допускается увеличение количества страниц;
  - floats корректно перемещаются, не теряя подписи и не «разрывая» смысл.

### 13.2. Качество перевода

- Стиль академический.
- Термины согласованы внутри документа.
- Перевод не ломает структуру (нумерацию, ссылки, формулы, DOI/URL).

### 13.3. Регрессия

- Должен существовать режим прогонки по корпусу `tests/pdf_regression_corpus.json` с генерацией отчёта.
- Для каждого кейса сохраняются артефакты и метрики:
  - число страниц;
  - наличие пересечений bbox;
  - наличие переполнения;
  - количество фиксированных элементов, прошедших визуальную проверку.

## 14. Интеграция в CLI/API (на уровне ТЗ)

- Добавить режим Variant B в `cli.py pdf ...` одним из способов:
  - `cli.py pdf reflow <input> -o <out> --lang ru` (новая команда)
  - или `cli.py pdf run ... --mode reflow`.
- В режиме Variant B выход по умолчанию должен соответствовать правилу имени файла из раздела 3.2.

## 15. Этапность (рекомендуемо)

- **MVP**:
  - DocumentDOM v1 + базовая классификация fixed/flow;
  - рефлоу текста в 1–2 колонках;
  - перенос на новые страницы;
  - базовые floats (figure + caption).
- **v1**:
  - таблицы (простые) как floats;
  - сноски;
  - метрики и regression runner.
- **v2**:
  - сложные таблицы, multi-page;
  - advanced anchoring;
  - улучшение OCR/scanned.
